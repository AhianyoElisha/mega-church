# 4. Basonta, the new Bacenta, member numbers, BENMP, and a treasurer

🔴 **Complex** — new domain concept, a repurposed one, a live-data migration
across 157 members, and a sixth role.

## Why

"Bacenta" was built as one collection doing two unrelated jobs: the church's
**service groups** (Choir → Biazo / Living Waters / Fresh Oil, Technical Team,
Ushers, Media, Dancing Stars) *and* the **places people stay** (Anloga,
Susuankyi, Oforikrom, Bomso, Asokwa). The church has clarified that these are
two different things with two different names, and that the second is what
"bacenta" actually means.

The live project is the constraint: 157 members, 12 groups, 66 membership rows,
all real. Every schema step is additive-then-migrate-then-clear, and nothing is
deleted before its copy is verified.

### What the live data settled, before any code was written

- The 12 groups split **7 service / 5 location**, not 12/0 — the five are
  already named "… Bacenta".
- **No member is in more than one location bacenta** (0 of 28), so
  one-bacenta-per-member loses nothing.
- All 28 are in **Alos Constituency**, unanimously. Asokwa is empty → Alos.
- 64 of 157 members have **no constituency**; 3 of 4 constituency heads have a
  member row (Hayford Budu does not).

## Decisions

| | |
|---|---|
| Bacenta membership | one per member — a **field**, `members.bacenta_id` |
| Basonta membership | zero or many — the **join**, `basonta_members` |
| Existing data | 7 → Basonta, 5 stay Bacenta; copy, verify, then clear |
| BENMP | field + registration/edit UI only, no automated send this round |
| Treasurer | tithe-category sends only, plus the shepherd read set |

## Tasks

### 1. Basonta ✅ done

Three collections structurally identical to today's bacenta trio, so every rule
survives unchanged: name unique per CATEGORY, `category_id === null` IS the
standalone case, membership written as a **diff**.

- `scripts/setup-appwrite.ts` — `basonta_categories`, `basontas`,
  `basonta_members` (with `pair_unique`)
- `lib/groups/server.ts` — the basonta half, a deliberate copy rather than a
  shared generic: the two shapes part company the moment a bacenta gains
  `constituency_id`
- `lib/groups/tree.ts` — `buildBasontaTree` **delegates** to the tested
  `buildBacentaTree`; it stops type-checking the day the shapes diverge, which
  is the reminder to give it its own copy then
- routes `/api/basontas`, `/api/basontas/[id]`, `/api/basontas/[id]/members`,
  `/api/basonta-categories`(`/[id]`)
- pages `/basontas`, `/basontas/[id]`; nav, proxy prefixes, `/my-groups` third
  tab; `deleteMemberCascade` purges `basonta_members`

**Validation:** `lib/groups/__tests__/basonta-tree.test.ts` — nesting, the
orphan bucket, empty categories, sort order, display name. *These caught a real
bug: the shorthand `basontas` in the delegation resolved to the function's own
parameter, giving every category the whole list. It type-checked perfectly.*

### 2. Member numbers — `2026001`

`members.member_no`, string, **unique index**. Year of registration + a
zero-padded 3-digit sequence.

**Claimed by the INSERT, not by a check** — the rule `notification_runs` and
`sms_messages.dedupe_key` already establish. Compute, create, let the unique
index reject a concurrent duplicate, recompute and retry (bounded). Decided
when creation is triggered, never reserved by the form.

Past 999 in a year the number grows to 4 digits and lexical order breaks within
that year, so the next value is computed by **parsing the trailing digits and
taking a numeric max**, never by `orderDesc`.

**Backfill** (`scripts/backfill-member-numbers.ts`, idempotent, `--dry-run`):
`2026001` Kwame Ofosuhene Peasah, `2026002` Bernice Serwaa Ofosuhene Peasah,
then constituency heads with a member row (Michael Kofi Agyei, Frank Incoom),
then everyone else by `$createdAt`. ⚠️ Hayford Budu has no member row — flag,
never guess.

**Validation:** unit tests for year rollover, 999→1000, and a gap after
backfill; dry-run shows the two named members first.

### 3. BENMP Partner

`members.benmp_partner` boolean, added **optional** and backfilled to `false` —
Appwrite cannot add a `required` attribute to a populated collection without a
default, and required-and-defaulted is refused. Registration and edit forms,
member detail, registry filter.

**Validation:** register a partner and a non-partner; filter the registry.

### 4. Treasurer

Sixth label. Shepherd's reads; the one write is a **tithe** SMS.

`/api/sms/send` accepts `admin` or `treasurer`, and a treasurer sending another
category is **refused by name with a reason**, never silently downgraded.

**Validation:** tithe send succeeds; birthday send refused by name; a write
anywhere else 403s.

### 5. Bacenta repurposed

`constituency_id` on bacentas; membership onto `members.bacenta_id`;
`members.care_of_member_id` for pastoral care, enforced by a pure
`careAssignmentProblem()` — not self, same bacenta, active, **no cycles**
(chains allowed). Carers need no account: it is a record, not a login.

**Validation:** unit tests for self / cross-bacenta / cycle / chain.

### 6. The migration

`scripts/migrate-basonta.ts`, `--dry-run` by default, re-runnable. Copy
categories → groups → memberships (bulk `createDocuments`), **verify counts and
that every row resolves**, then set `constituency_id` on the five, write
`members.bacenta_id`, and only then clear the moved rows. Steps 1–4 are
non-destructive on their own.

**Validation:** dry-run inspected; counts match after apply; re-run is a no-op.

Six PRs, each shippable. **1 and 5 must be live before 6 runs.**
