# Plan 1 — Foundation: graft semp's biometric stack onto PickLT's UI

🔴 **Complex** — split into the phases below; each is independently verifiable.

## Goal

A working church attendance system that is, in equal measure:

- **semp's behaviour** — the FS81 capture pipeline, NBIS matching, the matcher
  seam, the kiosk state machine, offline queueing, the provisioning pack. Not
  reimplemented. Extracted.
- **PickLT's appearance** — the same component library, icon sets, layout
  language and typography, re-themed white / yellow / black.

`PRD.md` holds the domain. `CLAUDE.md` holds the rules. This plan holds the
order of work.

## Next 16 notes (read before writing routes)

- Middleware is called **Proxy**. The file is `proxy.ts` at the project root,
  exporting `proxy` (or default). `middleware.ts` is gone.
- Route Handlers are uncached by default; `GET` can opt in with
  `export const dynamic = 'force-static'`. We never want that here.
- Dynamic route params are async: `{ params }: { params: Promise<{ id: string }> }`.

## Phase E — Attendance orchestrator

`lib/attendance/` — `types.ts`, `occurrenceResolver.ts`, `liveStats.ts`,
`scope.ts`, `server.ts`.

The two pieces of real design work:

1. **`activateOccurrence`** — reject with 409 when any occurrence is already
   `open`. This is the single-active-session invariant (PRD §2.2) and it lives
   on the server.
2. **Two-stage identify** — `lib/services/biometricService.ts`, ported from
   semp's `identifyAcrossScopes`. Restricted meeting: roster first, then all
   active members, so an unauthorised member is *identified* and told why
   (PRD §2.3). Unrestricted service: one stage, all active members.

**Validation:** unit tests for `occurrenceResolver`, `liveStats`, and the
two-stage escalation with a fake matcher — including the case that produces
`not_authorised` rather than `no_match`.

## Phase F — Routes + auth

`proxy.ts` for cookie-session gating. `lib/appwrite/server.ts` with
`createAdminClient` / `getAuthUser` / `requireRole`.

Routes: `/api/auth/*`, `/api/members/*`, `/api/meetings/*`,
`/api/occurrences/*`, `/api/attendance/{active,scan,manual,live}`,
`/api/biometrics/{enroll,templates,matcher-health}`, `/api/kiosk-pack`.

**Validation:** every mutating route rejects an unauthenticated caller with
401 and a wrong-role caller with 403, proven by hitting them with `curl`.
